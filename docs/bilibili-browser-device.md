# 本人浏览器设备修复

适用版本：Daily **1.14.0**、Cookie **1.6.0**。

适用于：扫码登录验证正常，但分享仍返回 `-403`。现有 QR 会话只有主站下发的设备标识，未必等于浏览器完成了设备初始化。本入口用本人正常浏览器的设备字段替换这一部分；是否解决当前账号的问题，仍需官方 `share=true` 的实机结果。

## 一次性设置

1. 在 Surge 更新 Daily 和 Cookie 两个模块/远程脚本，确认 Daily 面板显示 `v1.14.0`。已有有效账号会话无需重新扫码。
2. 在 iPhone“快捷指令”新建一个快捷指令，设为**在共享表单中显示**，接收类型只选 **Safari 网页**。
3. 添加 Apple 的**在网页上运行 JavaScript**操作，输入选“快捷指令输入”。把 [`scripts/export-bilibili-device.js`](../scripts/export-bilibili-device.js) 的完整代码粘进去。
4. 下一步添加 Surge 提供的 **Run Script / 运行脚本**操作，脚本名选/填 `Betty-Bilibili-Cookie`，参数使用上一步 JavaScript 的结果。不要把输出上传到网络或粘贴到聊天。
5. 按 iOS 提示允许该快捷指令运行网页脚本。若系统禁用了脚本，需要在“快捷指令”的高级设置中开启相应选项。

Apple 的网页脚本操作与共享表单用法见[官方文档](https://support.apple.com/zh-cn/guide/shortcuts/apdb71a01d93/ios)；Surge 的命名 generic 脚本与 `$intent.parameter` 见[官方文档](https://manual.nssurge.com/scripting/generic.html)。具体操作名称随系统语言变化；本仓未在用户手机上验证快捷指令 UI。

## 执行一次

1. 在 Safari 正常打开 [Bilibili 主站](https://www.bilibili.com/)，等待页面加载。若移动站缺少设备字段，切换“请求桌面网站”后正常打开页面。
2. 从该网页的共享菜单运行刚建的快捷指令。
3. Surge 通知显示“浏览器设备信息已导入”后，回到 Daily 面板手动刷新。

若提示设备字段不完整，不会导入。若提示账号验证失败、会话变化或保存失败，原已保存会话不变。不要反复换设备、扫码或清空任务记录来突破当日限额。

## 处理范围

- 只导出 `buvid3`、`buvid4`、`b_nut`，及存在时的 `_uuid`、`buvid_fp`、`b_lsid`，同时保留该浏览器的 User-Agent。
- 不导出 `SESSDATA`、`bili_jct`、账号 ID；已有账号凭据在 Surge 本地保留。导入校验只向 Bilibili 官方 nav 请求，关闭自动 Cookie 和自动跳转。
- Daily 沿用导入的 User-Agent 和设备信息。设备值稳定复用，不每日重新生成。
- 导入不清空分享、投币记录。仅同日明确业务拒绝两次、冷却至少 60 秒、确实更换为导入的浏览器设备且未用过恢复的分享，允许一次手动恢复；准备前持久化占额。准备失败、超时、已接受、HTTP 拒绝、结果未知或已达到三次的记录不能增加写入机会。
- `_uuid` 或设备字段存在，不作为“设备登记成功”或“经验到账”的证明。扫码重新登录会建立新的 QR 会话；确有需要时再导入本人浏览器信息。

## 手机验收

以 Daily 通知中的官方登录/观看/分享状态、官方投币经验、账号等级经验前后值为依据。`HTTP 200`、接口 `code=0`、Cookie 导入成功及本地测试通过都不能替代账号实机验收。若当前账号在官方客户端也被拒绝，本模块不能保证解除服务端限制。
