# Bilibili Daily 1.11.0 审计与修复

日期：2026-10-05（北京时间）。基线：远端 main `377440302ed0805051d842e8a39482484ddbcafa`，Daily 1.10.0、Cookie 1.5.0。

范围为现有每日等级经验任务：登录状态、观看、分享、投币、大会员经验、Panel、cron 和 Cookie 读取边界。当前版本没有漫画或直播签到；本次不恢复历史上已移除的功能。Cookie 登录实现与分享请求参数保留既有实机验证结果。

## 确认并修复的问题

| 问题 | 原行为与影响 | 1.11.0 处理 |
| --- | --- | --- |
| 网络失败误判 Cookie 失效 | nav 超时、HTTP 403/5xx、响应异常都要求重新扫码 | 区分查询失败、认证错误与账号拒绝；有效验证后清理旧失效标记 |
| 身份校验不完整 | metadata UID 可为空，Cookie 内 UID 未与登录 UID 三方比较 | 写任务前核对 Cookie、metadata 与 nav 的 UID，并拒绝控制字符 |
| 查询阶段丢失认证 / 风控错误 | 每日状态、经验、视频查询把错误转成空值，甚至继续写任务 | 明确认证、封禁、风控 / 限流错误传回主流程并停止；`-403` 保持单项拒绝语义 |
| HTTP 5xx 的 GET 重试未生效 | 遇到 JSON 错误体提前返回，绕过重试条件 | 仅按原重试次数重试 GET；POST 不自动重试 |
| 投币缺少跨运行记录 | 超时或中断只停止当前进程，再刷新可能再次扣币 | 每账号、北京时间每天一份本地额度记录；发送前持久化占额，明确结果后结算 |
| 投币结果不确定仍可能继续 | 500 等未知错误继续换视频，经验增长也可能被错误归因 | 超时、跳转、HTTP 异常、未知业务结果保留占额并停止当天投币；不凭经验上涨猜测是哪次请求成功 |
| 经验延迟导致重复补投 | 本地成功次数不持久化，下次只看到旧经验又补投 | 已明确成功的额度跨次保留；两处官方经验值不一致时采用较高的已确认值 |
| 结果显示不真实 | 本地估计替代官方经验；余额不足仍说全完成；最终查询失败用旧值作最终结果 | 官方经验与本次成功投币数量分开；余额不足显示部分完成，最终查询失败明确标注，余额读不到显示未知 |
| 未限制整轮运行耗时与上下文 | 候选循环可能超过 300 秒；跨日或重新扫码后仍沿用旧状态 | 270 秒内部预算；每次请求与等待检查日期、当前 Cookie 与运行锁，变化后结束本轮 |
| Panel 缓存过期与覆盖 | 昨天 / 上一账号的完成结果沿用；重复实例把结果改成“正在运行” | 缓存绑定日期、账号、版本；仅持锁实例保存结果；非按钮 Panel 调用只读本地 |
| 数值类型宽松 | `false`、空数组等可被当成 code 0 / 余额 0 | 仅接受有效数字或非空数字字符串；不完整经验值不作投币依据 |
| 大会员请求上下文与多余查询 | 缺少现有会话的 buvid 字段，非大会员也额外查询等级经验 | 按当前上游请求形态携带已验证 buvid3；非大会员省去无用查询 |

## 持久化与恢复

- 新键：`betty.bilibili.daily.coin_budget.<uid>`，只保存版本、日期、已占额度、待确认标记，不含 Cookie。
- 明确成功：保留当日额度，即使经验尚未同步也不再次花掉这些额度。
- 超时、进程被终止、结果保存失败或记录损坏：当天不再投币，次日恢复。其余可独立执行的任务继续按各自结果判断。不要通过删除记录来强行补投。
- 未使用真实账号做写操作；模拟投币记录没有写入手机。升级不要求清除 Cookie 或既有分享去重记录。
- 每次运行最多补到 5 枚的普通任务目标；其他客户端同时投币仍存在服务端查询与写入之间的竞争，脚本无法提供跨客户端事务保证。
- 08:00 cron 随设备时区；B 站任务日期与本地去重按 UTC+8。自动 Panel 刷新不会执行网络请求或补签到。

## 依据

- [Surge JavaScript API](https://manual.nssurge.com/scripting/api.html)：触发来源、请求状态、超时秒数、禁用自动 Cookie / 跳转、持久化写入返回值。
- [Surge cron](https://manual.nssurge.com/scripting/cron.html) 与 [脚本运行时限](https://manual.nssurge.com/scripting/overview.html)：正常 cron 不带 Panel 输入；脚本须在 timeout 前完成。
- [BLTH 当前接口实现](https://github.com/andywang425/BLTH/blob/3fd9d80086f303985ec4d2dad7c9947861da2805/src/library/bili-api/index.ts)：本次读取的上游 HEAD。确认分享仍采用 `pc_client_normal`，大会员经验请求使用 mid / buvid / csrf。第三方源码只作为请求形态依据，不代表 B 站官方承诺，也不证明此账号一定通过风控。
- 既有分享实机依据见 [会话与分享说明](bilibili-session-share.md)。未因上游新增参数而整体替换已验证的观看、分享和投币请求。

## 验证边界

新增隔离回归覆盖网络 / 认证分类、身份不一致、GET 重试、跨运行投币上限、未知结果、持久化失败、日期切换、账户切换、运行锁、余额不足、经验延迟、最终确认、真实 cron 入口形态与完整任务成功路径。测试仅使用假 Cookie 和本地模拟响应。

本轮新增 45 项测试；全仓库共 397 项通过。脚本语法、模块元数据 / 引用以及固定 Config 版本的 18 项 General 契约校验均通过。时区相关场景另在 Asia/Shanghai 环境检查，日期夹具与北京时间去重均正常。

全仓库测试另发现一个基础面板测试将固定 Unix 时间戳硬编码为北京时间日期，导致 UTC 环境失败；仅将该测试的到期时间夹具改为本地同一日的中午，未修改基础面板脚本。

本地语法、模块一致性、Config 契约及行为测试不能代替 iPhone + Surge 的真实任务验收。B 站接口无此用途的稳定公开服务承诺，风控、异步记账、手机后台调度与网络状况仍需看实际运行结果。更新后 Panel 显示 `v1.11.0` 才表示已加载新版脚本。
